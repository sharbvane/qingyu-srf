# v0.7.1 验证记录

正式包：`Qingyu-0.7.1.apk`，版本代码 11，105,805,000 字节。
SHA-256：`2e634fe7bce5afae00745d64520bc007476ef9da0ec362fd8fd265f91bd0ffe8`。

本轮使用项目独立的 Android 15 / API 35 / x86_64 模拟器，没有操作用户手机。测试辅助包与正式发布包分别记录，模拟器通过不等于 ARM64 真机验收。

## 构建与覆盖升级

Java 17、Gradle 8.9、SDK 35、NDK r28b；核心检查、Release R8、正式签名与 Android 测试包构建通过。包名、独立 Release 证书、API 26–27 兼容证书及 API 28+ 签名谱系不变。最终 APK 的签名、ZIP 16KB 对齐及九个原生库的 LOAD/RELRO 审计通过，报告见 [release-package-v0.7.1.json](release-package-v0.7.1.json)。SDK 依赖、原生库与词库资源没有更换，额外语言模型仍不预置。

原 v0.7.0 正式包覆盖安装此最终 v0.7.1，`RELEASE_MIGRATION_SEED_PASS` 和 `RELEASE_MIGRATION_VERIFY_PASS` 通过。应用 UID、私有偏好、文件哨兵、已有用户词典及三个个性化学习文件均保留；检查不记录用户词典或学习内容。没有卸载、清数据或改变存储格式。

## 候选更新与编辑面板

录像中的候选空白对应旧路径每次输入先发布空快照、再等待异步解码。现在同模式且仍有输入时保留已有候选和匹配释义；新结果到达后直接更新。真正清空、模式或会话变化仍清理旧状态。旧画面的点击会在按序执行的新查询结果中重新按词语匹配，不能复用过期序号；详情和上滑仍受当前版本检查保护。

匹配释义按词语、语言和模型状态复用，相同批次不重复取消、加载。原始拼音变化但词表不变时保留触控和滚动；真实词表变化仍取消失效手势。没有为这些更新新增清空动画、额外高度或输入等待。

同源 Debug 包实际执行了候选快照、释义、轻点、长按、上滑、拖动、惯性滚动、清空边界和过期版本保护检查。新编辑面板在 320/480/600 dp 宽、314/252/112/90 dp 可用高下检查布局、按钮顺序、图标、48 dp 触控区域、选中状态更新、连续删除及取消；短高度使用原生滚动区保持按钮尺寸。编辑历史边界与实际个性化学习另通过 Debug 检查：12 次九键选择的持久计数从 174 增至 186，重开后在前 3 项；一次中文预测的全局与上下文计数各增加 1。

最终正式包在 4KB 页、字体 1.0 的 `ImeV71Instrumentation` 通过全部 **41 组**。覆盖既有九键布局、大小写与数字滑选、连续音节、简拼/全拼/混拼、滚动、分词、回退及密码输入；原生输入框和独立进程 Chromium textarea 的删除、撤回、剪切、粘贴、原位置翻译替换及外部修改保护；新圆盘四向移动、行首行尾和选区伸缩；四次旋转/重启输入/释义切换；全拼、九键及英文输入删除的候选连续性；异步释义不关闭展开候选。

同一正式包在 4KB 环境的 `ImeV6Instrumentation` 通过全部 **56 组**：常用词、拼音歧义及误触纠错、自然整句、12 次跨 Android 设置应用切换、40 轮选词删除、快速展开收起、多语言释义/详情/上滑同步、日语及德语模型删除后重新下载，以及中文、英文、数字、剪贴板、密码与高度设置的既有回归。

同一最终 APK 在官方 `google_apis_ps16k` revision 5 镜像、实测 16384 字节页、字体 1.3 下，`ImeV71Instrumentation` 亦通过全部 **41 组**。新编辑面板在放大字体下的实际截图检查未发现按钮遮挡、挤压或越出键盘区域。

本轮真实 Android SQLite 与九键图检查通过 `ALL_INPUT_DICTIONARY_CHECKS_PASS`，英文 121,167 个词形的补全/纠错/预测检查通过 `ALL_ENGLISH_ENGINE_CHECKS_PASS`。常用全拼、首字母、混拼、分段选词与持久学习保持；完整数据见 [input-language-results.txt](input-language-results.txt)。这些批量检查的耗时只是诊断数据，不是手机按键延迟或帧率承诺。

## 翻译与原文保护

直接辅助接口使用同源 Debug 包（SHA-256 `87ebf1ecd5e14c287eeb71c4609f9e9355a3185304f8747ccc49537770656660`），`ALL_EDITOR_TRANSLATION_CHECKS_PASS` 在 4KB 环境通过 **9 组**。实际端侧检查中文及六种外语识别，六语言中外双向翻译、整句英文语序、中日紧贴内容、日语共用汉字、无选区与混合内容规则、URL/邮箱/代码保护、格式、请求取消和模型代际变化。该包的翻译逻辑与最终正式包一致；最后一次正式构建只进一步调整了状态提示用语。正式包另由真实编辑面板验证 R8 后的输入与翻译行为。

新增仅操作真实编辑面板的 `EditorV71Instrumentation`，同一个最终正式 APK 在 **4KB / 字体 1.0** 和 **16KB / 字体 1.3** 分别完成全部 **7 组**。实际检查未选区「你好こんにちは」、选区「开发こんにちは」只翻译中文，原生日语句子保留；英语、日语、法语、德语、俄语、西班牙语选区分别识别并译为中文，整句英文包含朋友与短视频语义，原标点、数字、Emoji、CRLF 后缀保留，所有替换可撤回。这些检查调用 R8 后的真实 InputConnection 与面板，不依赖 Debug 辅助 API。

英文完整句子作为一个文字片段交给模型，普通单词间的单个 U+0020 空格随译文自然调整。Tab、NBSP、重复空格、换行、原标点、数字、Emoji 及受保护内容保持原位置；不是逐字节保留所有普通词间空格。替换前仍核对全文和选区，失败、内容变化或取消不修改原文，成功替换可按编辑顺序撤回。

真实识别暴露单独的日语「見」会被识别为中文，而相邻语法「見ま」为日语。因此紧贴假名的汉字段同时检查独立片段及相邻假名上下文，仅全部可信为中文才翻译。短文本、中日共用汉字及混合语义仍有歧义，不确定片段保留原样；模型译文准确性没有普遍保证。

## 失败与复测

失败证据保留。候选保留改变了测试等待语义：旧测试发现任意旧候选就立即点击，现已等待最新查询就绪后判断最终结果。浏览器测试曾依赖后台输入框或 JavaScript 自动聚焦，现改为对实际前台 textarea 触控聚焦。横屏释义开关在滚动区下方，旧辅助函数把不可见的「隐藏释义」误判为不存在而寻找错误的「显示释义」；辅助函数现先滚动找到实际按钮。这三处只修正测试定位与等待，没有据此改变生产输入或模型实现；修正后同一正式 APK 完成上述 41 组检查。

完整输入回归首轮在德语模型重新下载时网络超时，仍正常中文输入；配置模拟器网络后，同源 Debug 辅助检查实际完成 36,154,421 字节下载、测得德语模型占用并验证六语言翻译。随后同一正式 APK 完成上述 56 组，包括日语、德语删除重下。没有为这一网络问题修改模型下载代码，也没有把其余语言已缓存的就绪检查称为本轮全部重新下载。

16KB 环境的直接 Debug 翻译辅助测试两次进程崩溃，未计为通过：首轮 `MLHandler` 的 GMS Tasks/JIT 路径发生 PC 0 SIGSEGV；第二轮在 DataTransport/ML Kit 翻译遥测的 JIT 路径发生 SIGSEGV。没有新汉字/假名识别方法的崩溃栈，但不能据此认定根因或排除应用问题。旧版记录中的引用队列退出不能被称作同一个已确认故障。本轮没有改动 SDK、原生库或系统运行时规避；正式包与 Debug 辅助结果分别记录。

16KB 正式包补充编辑翻译检查的首轮亦发生 `ReferenceQueueDaemon / ReferenceQueue.enqueuePending:239` 空指针退出；同一 APK 单独复测后完成上述 7 组。正式包的 41 组输入检查和 7 组翻译复测通过，不代表该环境没有偶发崩溃或长期稳定性风险，相关根因仍未确认。
