# 轻语输入法 · Android 产品规格

当前实现范围：v0.2，2026-10-06。本文记录产品行为和工程边界，不代表本轮测试或发布已经完成。具体设备、验证结果和安装包以对应版本的验证记录与发布说明为准。

## 产品定位与 v0.1 背景

轻语首先是一款中文输入法，优先保证输入正确、稳定和跟手，让用户在正常输入时顺便接触外语。v0.1 的起点是 Android 中文全拼与本地英文候选注释：输入 `kaifa`，候选“开发”上方显示 `develop`，轻点候选只提交“开发”。这些基础原则继续适用。

优先顺序：输入正确与稳定 → 按键和候选响应 → UI 跟手与编辑兼容 → 候选质量 → 简洁视觉 → 外语辅助。v0.2 在此前基础上加入九键、英文候选、编辑工具与端侧翻译；原先“只支持中文到英文、无网络权限、没有模型”的范围属于 v0.1 历史，不能继续作为新版事实。

普通点击始终输入原候选。长按查看释义，上滑候选才明确请求输入译文；译文不会自动替换普通中文输入。词典安装、查词、模型检查、下载、推理和失败均不得成为中文全拼输入或提交的前置条件。

## v0.2 已实现的十三个功能域

“已实现”表示有当前代码和数据路径，不等同于真机长期验收通过。

| 功能域 | 当前行为与边界 |
| --- | --- |
| 1. 系统输入法与启用设置 | Android 系统 IME，应用提供启用、系统选择器、试打与设置入口；适配编辑器输入类型和回车动作 |
| 2. 简洁导航 | 键盘上方固定五个入口：更多、文本编辑、Emoji、键盘模式、收起输入法；工具面板复用键盘区域，并可返回键盘 |
| 3. 文本编辑 | 左右光标、行首/行尾、选择、全选、复制、剪切、粘贴；优先使用宿主编辑器的系统操作，兼容性仍取决于宿主应用 |
| 4. 本地剪贴板 | 最近最多 100 条去重文本，可点击粘贴、长按删除和清空；设置可关闭记录，密码字段及系统标记敏感的剪贴板不留历史 |
| 5. 中文全拼 | AOSP PinyinIME 原生解码器、整句及分段选词、隔音符、候选横向浏览与展开分页；九音节原生边界之外的输入保留并分段处理 |
| 6. 中文九键 | 离线读音到数字索引与词频排序，支持候选、短词分段及有界整串组合；它是独立九键适配，不是 AOSP 全拼引擎的数字键模式 |
| 7. English 输入 | 补全、拼写建议、大小写与大写锁定；空格提交实际输入的拼写，只有明确选择候选才采用建议，不静默自动纠错 |
| 8. 上下文下一词预测 | 组合串结束后根据编辑器附近上下文给出中英文续词；英文为词频、bigrams 和本机计数，中文结合 AOSP 续词、词典词尾和日常搭配，均是轻量统计预测 |
| 9. 候选释义语言 | 中文候选可选英语、日语、法语（en/ja/fr），默认英语；英文候选默认对应中文（en→zh），不随中文释义语言切换；显示开关只管理候选注释 |
| 10. 候选三种动作与整串翻译 | 轻点输入原词、长按查看完整释义、上滑输入译文；翻译源包含当前选词对应的完整组合串，失败或过期结果不提交 |
| 11. 端侧词句翻译 | 常用词和短语优先查本地；本地未命中时，仅在模型已就绪后用 ML Kit 端侧模型补充；用户显式点击下载，模型下载要求 Wi-Fi |
| 12. 日常按键与手势 | 中文/英文标点、数字/符号及混输；长按字母数字、中文逗号隔音符、连续退格、退格左滑删除、空格左右滑动光标、候选横向滑动；Emoji 分组面板直接输入 |
| 13. 外观、反馈与基础设置 | 墨绿色浅色/深色/跟随系统，两种键帽风格，78%–124% 连续高度，震动和按键预览；词频、剪贴板与释义显示均有设置入口 |

英文索引有 **121,167 个词形**，本地英文到中文释义有 **20,126 条**，二者不是相同覆盖范围。词形变化可尝试词干查义，但不能承诺每个英文建议均有本地释义。缺失项在相应模型就绪后异步补充，否则留空。九键索引有 121,070 个读音项；这些数量是当前数据清单的统计，不代表准确率。详见 `third_party/input-data/manifest.json`。

不加入账号、社区、广告、学习任务、打卡、表情商店或云端文本翻译。端侧翻译模型不参与中文候选生成，也不将轻量输入预测包装成神经语言模型或成熟商业输入法级能力。

## 候选栏与翻译语义

- 原候选为第一视觉层级，辅助释义为第二层级，字号更小、颜色更弱、单行省略。
- 候选宽度由原候选决定，辅助语言长度不改变候选位置；注释及归属标识使用预留位置，异步返回不拉伸键盘。
- 注释开启时无释义留空。关闭注释后停止该批注释请求并作废迟到结果；长按或上滑是另行明确发起的翻译动作。
- 全拼候选的长按/上滑源串包含此前已经选择的片段、此次候选，以及原生九音节限制之外仍需解析的 tail。解析只用于预览，恢复原引擎状态与候选身份；未解析字母保留，不能删掉后假装整句成功。
- 九键按候选实际消耗的数字长度继续解析剩余数字；无法解析的剩余数字保留。英文动作翻译当前英文候选，预测动作翻译所选续词，不读取整段聊天记录作为翻译源。
- 只有当前会话、输入代际和动作请求仍一致时，才可显示详情或输入译文。下载中、缺词、空结果和错误提供状态说明，保留原输入。
- 详细英文词典义项用于阅读，不把多个义项、交叉引用或词性说明当作可提交译文。模型译文和本地词典来源分别标示；模型结果显示 Google 要求的原始归属标识。

按键立即反馈，轻量动画辅助面板切换与抬手恢复。横屏重新计算布局和高度；长按预览、工具面板和候选应避免导航栏遮挡。用户提供的参考截图只解释信息结构，不授权复制参考产品的品牌、UI 或代码。

## 输入、词典安装与翻译线程

1. 主线程处理触摸、绘制和 `InputConnection`；不在 touch handler 中安装词典或运行模型。
2. 单一 decoder worker 串行处理全拼搜索、选择、删除、九键/英文搜索、预测和候选源串预览。中文与直接字母、数字、标点的提交保持输入顺序；输入语义事件不能为提速被丢弃。
3. 辅助输入数据库、英文词形和 bigrams 的安装/读取初始化在一次性的独立 `qingyu-data-install` 线程完成，再将就绪对象交给 decoder；不会占用中文解码队列或释义队列。AOSP 核心的初次打开仍由自身输入 worker 管理。
4. gloss worker 安装释义数据、查询本地索引并安排异步模型任务，与原生引擎搜索不共用队列。本地查义覆盖当前有界候选快照；模型只补充当前可见页的缺义候选。
5. 注释请求延后约 100 ms 合并，只合并辅助请求；可见页的模型补充每次串行推理一条。横向滚动或展开分页启动新的批次 nonce，取消旧批次剩余队列；迟到结果须通过批次、会话、代际、语言及显示开关核验。
6. 只有下载按钮调用模型下载 API，并配置 Wi-Fi 条件；检查本地模型和输入候选不会调用下载。推理异步完成，不持有中文引擎锁。

用户学习计数在合适的生命周期边界保存，不逐键同步写磁盘。关闭服务时清除回调、释放数据库与模型客户端，并停止 worker。独立队列避免代码上的同步等待；同机 CPU、内存与 I/O 争用对体验的影响仍需测量。

官方翻译 SDK 当前 ARM64 二进制的 GNU_RELRO 末端不满足 16 KiB 页兼容要求。在 ARM64 且系统页大于 4 KiB 的进程中禁用 SDK 翻译与模型下载，继续提供基础输入、本地释义和词典详细义项；原因与恢复条件见 `third_party/mlkit/SOURCE.md`。

## 系统编辑与隐私

Android service 适配 `EditorInfo` 与回车动作；组合串用 `setComposingText`，实际提交用 `commitText`。光标、选择、跨应用与焦点变更需要同步平台组合区域与引擎状态；结束组合串后再执行会改变编辑位置的操作。

密码字段固定直接输入，关闭候选、释义、学习、放大键帽和剪贴板记录，禁止复制/剪切密码。`IME_FLAG_NO_PERSONALIZED_LEARNING` 关闭新增学习，但允许正常中文输入及可选释义；已有学习数据不会自动擦除。记录开关关闭也不等于清空历史，历史清理由剪贴板面板的明确操作完成。历史最多 100 条，超大文本不保留，应用备份关闭。

v0.2 声明 `INTERNET` 和 `ACCESS_NETWORK_STATE`。拼音、英文建议、剪贴板和译文推理在本机处理，不调用云端文本翻译接口，输入原文和译文不附到下载请求。ML Kit 可能独立联网做模型、配置、兼容性和诊断，并发送设备/应用信息、安装标识、语言配置、输入输出长度、耗时、事件与错误码等元数据；不能宣称新版“完全无联网/无遥测”。显式下载与 Wi-Fi 条件约束模型下载，不代表所有 SDK 请求都由用户下载按钮触发。[ML Kit 数据披露](https://developers.google.com/ml-kit/android-data-disclosure)、[ML Kit 隐私条款](https://developers.google.com/ml-kit/terms)。版本、归属与具体说明见 `third_party/mlkit/SOURCE.md`。

临时按键诊断日志已移除，产品日志不记录用户输入文本。普通删除先处理选择区，再按 Unicode code point 删除，避免破坏 UTF-16 代理字符；复合 Emoji 的字素簇行为仍需专项验收。抬手、`ACTION_CANCEL`、窗口隐藏和销毁必须停止重复删除及长按。[Android IME 指南](https://developer.android.com/develop/ui/views/touch-and-input/creating-input-method)、[InputConnection 参考](https://developer.android.com/reference/android/view/inputmethod/InputConnection)。

## 数据、许可与跨平台边界

`core/` 保存不依赖 Android 的候选快照、全拼与英文引擎及 provider 契约；`app/` 保存 Android service、Canvas UI、工具面板、SQLite 与 ML Kit 适配、JNI 和打包。数据处理代码、原始来源和编辑修改在 `tools/`、`third_party/` 与 `assets_sources.md` 中记录。

轻语自有代码当前采用 GPL-3.0-only；AOSP Apache-2.0、CC-CEDICT 衍生数据 CC BY-SA 4.0、SCOWL 原许可、jieba MIT 与 Google SDK/模型条款各自保留。端侧模型独立下载，不是轻语原创 GPL 数据。详见 `LICENSE-THIRD-PARTY.md`。

输入模式与辅助语言是独立维度。en/ja/fr 是当前中文释义选项，韩语和西班牙语仍是未来扩展；iOS 尚未实现。后续 iOS 重用数据格式、输入/注释协议和可提取的 C++ 核心，单独适配 `UIInputViewController`、`textDocumentProxy`、平台安全输入与下一键盘。Java UI、Android SQLite/ML Kit 包不能直接成为 iOS 二进制。[Apple 自定义键盘指南](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/CustomKeyboard.html)。

## 性能目标与验收记录

以下仍是工程目标，不能由编译成功、功能存在或单次引擎微基准推导出达标。

| 指标 | 建议目标 | 记录方法 |
| --- | --- | --- |
| 按下到反馈 | 下一帧反馈 | 触摸时间与 frame trace |
| 热状态候选生成 | p95 ≤ 30 ms | worker 计算和排队分开 |
| 输入到候选显示 | p95 ≤ 50 ms | 输入序号与快照显示时间 |
| 热状态键盘弹出 | p95 ≤ 200 ms | onStartInputView 至首帧 |
| 辅助数据首次安装 | 先显示键盘，中文核心独立就绪 | 首装、升级、损坏恢复分开 |
| 动画与滑动 | 适配设备刷新率，无周期性卡顿 | 60/120 Hz、模型并发与空闲对照 |
| 稳定性 | 无持续内存增长或 ANR | 长时轮测、PSS、热量与功耗 |
| 翻译隔离 | 故障时输入和提交继续 | 缺词、无模型、下载失败、推理迟到 |

验收须覆盖三种输入模式、混输顺序、候选三种动作及完整 tail、编辑/选择、剪贴板清理和敏感剪贴板、密码、模型有无与语言切换、连续输入/删除、横竖屏、主题/高度、跨应用/输入法及真实读屏。特别检查模型未下载时的离线首装体验，以及模型计算时的输入排队和 UI 帧率。

可安装和正常输入是阶段交付目标。能否长期替代主力输入法，仍需要真机、真实宿主应用和持续使用反馈；先修输入问题，再扩大预测质量、译词覆盖与语言种类。此处不记录本轮测试通过数量、签名校验值或发布结论。
