# v0.3.0 离线输入语言数据

英文输入采用原生 Java `EnglishEngine`：121,167 个经过 SCOWL 拼写与词形规则验证的英文词形，支持前缀补全、单编辑距离纠错、低匹配时常用词二编辑距离纠错、大小写保持、上下文下一词、用户新词与搭配计数。输入原文始终作为可选候选保留，不强制替换用户输入。

17,580 条下一词记录来自四部原始英文公版文学作品的聚合计数与本项目原创日常搭配补充。只部署词频与搭配计数，不部署作品正文。每个前词最多 24 个基础后词；用户搭配计数另行保存。语料不是现代神经语言模型，罕见专业表达或复杂语境的预测仍有局限。

中文九键采用完整 CC-CEDICT 拼音索引，共 121,070 个真实词目读音，按 jieba 词频排序，支持拼音未输完时补全、词组、句子分段、个人词频和已用上下文搭配。每个候选保留精确的已消费数字数量，选入前缀后未消费的数字继续解码。九键歧义通过有界词频分段与常用搭配评分处理；现代九键纠错模型、滑行词识别不在本次实现范围。

英文候选中文释义来自 CC-CEDICT 反向单词索引，共 20,126 条精确索引，另有原始词形还原、常用词人工简义。它覆盖常见词和许多派生词，但不宣称全部 121,167 个词形均有精确中文词义。词义缺失不影响英文候选、上屏或下一词预测。

中文下一词优先复用 AOSP `im_get_predicts`；JNI 只接收最多 7 个 BMP 汉字的连续尾部、最多返回 64 个短词，仅在拼音合成已完成后查询。CC-CEDICT 续词、日常搭配及本机计数作为补充。预测查询不改变正在输入的拼音与候选状态。连续选入预测最多 3 轮，预测栏最右「X」立即清空并抑制当前预测；新的实际输入开始下一条预测链。

候选 header 始终保留固定高度，空闲、拼音和预测状态不会改变键盘边界。展开候选使用独立网格占用原有键盘 body，高度遵守父容器 EXACT 尺寸；竖屏每页 12 格、横屏 6 格，最小高度时按字体度量调整两行字的字号与基线。英文释义和词性结果异步补充，不改变词条宽度。再次点同一顶部导航图标关闭对应面板，面板中不再提供单独的「返回键盘」按钮。

中文全拼默认小写解码；单次 Shift 的下一个字母直接输出大写英文，快速双击 Shift 锁定大写，均不进入拼音解码。普通字母长按后左滑选择大写、右滑选择小写；带数字的字母键提供左侧大写、中间小写、右侧数字，松手直接提交选中字符。九键、英文候选、标点和空格滑动光标继续使用原有路径。

`input-v3.db` 的既有中文表增补真实 jieba 原始词性标签，120,355 个中文词中 87,160 个有 exact 标签；来源、数量与输出 SHA 在 `third_party/input-data/manifest.json`。名词、动词、形容词、副词和虚词使用协调的低饱和文字色，浅色/深色及按压背景保持可读对比度；未知词、其他标签和英文候选为中性色。标签是词典默认词性，不推断当前句子中的词性，也不按文字 hash 或译词的反向映射猜测。批量 POS 查询最多 128 个词、缓存最多 1,024 条，在辅助线程执行，失败返回空标签。私有安装路径升级为 `input-v3.db`，不复用 v0.2 无 POS 列的旧库；既有 `english-learning-v2.tsv` 和 `chinese-learning-v2.tsv` 保留个人词频。

`PinyinEngine.previewCandidate(id)` 为候选详情与整句翻译解析完整待输入句子，包含已经选定的中文前缀、已经完成的原生分段及九音节边界后的全部输入。临时解析期间禁用学习；随后恢复原始拼音、固定选词分组、分段列表和同一个候选快照，原候选 id 及连续退格行为保持有效。不能解析的字母保留在预览结果中。该操作只能在输入工作线程执行。

辅助输入数据库、英文词形和 bigrams 的初次安装/读取由一次性的独立 `qingyu-data-install` 线程完成，再把就绪对象交给串行输入工作线程。输入引擎、九键 SQLite 查询与学习保存归输入线程所有；英文释义与中文 POS 查询单独同步保护，可由释义线程调用。词库安装不占用中文解码或释义队列。英文个人词/搭配总计最多 4,096 条，中文个人词/搭配总计最多 2,048 条；只保存词或最多 6 字上下文尾词及计数，不保存完整编辑器文本。禁用学习/密码/禁止个性化学习场景不产生新计数。

候选注释延后约 100 ms 合并，本地查义覆盖当前有界候选快照；缺义模型补充仅处理可见页，每次串行一条。滚动或分页会更换批次 nonce 并取消旧队列剩余请求，迟到结果不会覆盖新页或新输入。默认 APK 仅含中英文词典和中英常用短语；日语、法语没有内置本地短语或模型。用户在「更多 → 释义显示语言 → 翻译模型管理」或应用设置的同名页面连接 Wi-Fi 主动下载后，才提供对应语言的模型释义与句子翻译；页面支持状态与删除。正常打字或选择语言不会发起下载。官方 SDK 的 ARM64 GNU_RELRO 存在 16 KiB 页限制，ARM64 且页大小大于 4 KiB 时禁用模型路径，只保留本地中英输入与释义，详见 `third_party/mlkit/SOURCE.md`。临时逐键诊断日志已移除。

数据重建：`python tools/build_input_dictionary.py`，快照保存在项目 `.cache/input-v2`，所有来源、下载 hash、输出 hash、人工修改与许可证在 `third_party/input-data`。SCOWL 及 jieba 许可证全文已嵌入 APK，CEDICT 衍生部分继续遵守 CC BY-SA 4.0。

检查入口：`pwsh -NoProfile -File tools/test-input-data.ps1` 检查真实词库、补全、纠错、上下文、学习计数、隐私与持久化恢复，以及 Android SQLite 的九键全词、短语分段、40 位长串、反向释义、中文预测和 POS 批量查询。`tools/test-engine.ps1` 检查 JNI 原生预测 100 种上下文和拼音状态隔离，并运行原有连续输入/删除/随机长串检查。`CandidateLayoutCheck` 检查固定 header、X 共享边界、最小高度的网格文字与词性配色；本轮实际结果以 [v0.3.0 验证记录](validation-v0.3.0.md) 为准。耗时来自桌面 Java/Android 模拟器引擎调用，不代表真机总输入延迟。
