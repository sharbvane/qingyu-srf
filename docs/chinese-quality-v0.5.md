# v0.5 中文候选回归与边界

测试在 Android 35 x86_64 模拟器中使用实际 Java → JNI → AOSP 解码器和 Android SQLite。没有安装专用输入引擎，也没有用源词典直接查询替代候选生成。每例逐键输入后检查完整候选排名、释义所用完整句子预览、原快照和候选 ID 恢复、选词提交，以及逐键连续删除。

命令：

```powershell
./tools/test-chinese-quality.ps1 -Baseline -Dictionary .tools/pinyin-model/dict-v0.4.dat -SkipNativeBuild
./tools/test-chinese-quality.ps1 -SkipNativeBuild
./tools/test-chinese-quality.ps1 -Acceptance -SkipNativeBuild
./tools/test-chinese-upgrade.ps1
./tools/test-engine.ps1 -SkipNativeBuild
```

这是 396 例固定功能回归语料，覆盖常用词、现代词、多音节词、多音词、拼音歧义、明确音节边界、整句、轻微误拼、规范单音节和 ü 拼写；它不是随机抽样的中文准确率估计。词库不包含针对这套语料的补词或排序特例。

原始模型 SHA-256 为 `6bf0bbde4e3134cce38d08524a9f4dc1af40435243c8e36b38eb68d1e14462b2`，新模型为 `ae80997b6e2b2de23bc11276767a15cd00b1e8e6308823a2761769d811a3513a`。完整原始输出分别保存在 `chinese-quality-baseline-v0.4.txt` 和 `chinese-quality-v0.5.txt`，保留每例输入、候选和实际排名。默认严格模式的非零结果另存于 `test-results/v0.5-chinese-quality-strict.txt`。最终 `-Acceptance` 复跑全部 396 例，393 项日常验收通过，另 3 项开放语义评估仍失败并逐例输出；它不代表完整评估全通过。

`anzhuo → 安卓`、`dangang → 单杠`、`kuaidi → 快递`、`gaotie → 高铁`、`erweima → 二维码`、`rengongzhineng → 人工智能` 均为第一候选。`dan'gang` 与没有分隔符的 `dangang` 都可命中，而 `dang'ang` 保持用户明确指定的读音边界。普通 `tian / jian / yuan / xian` 的首项分别为天 / 见 / 元 / 先，提案、预案、西安等其他合法切分仍可选。

`lve → 略`、`nve → 虐`、`gonglve → 攻略`、`celve → 策略` 和旧输入 `lue / nue` 均首位。仅追加完整音节等价索引查询，不改原字母；`nver → 女儿` 保留原路径，没有被直接替换为其他读音。

`woxiangqubeijing → 我想去北京`、`jintiantianqihenhao → 今天天气很好`、`woxihuanchipingguo → 我喜欢吃苹果` 均为第一候选。`nohao / nihaoo / niho / nhiao` 的“你好”均为第一候选，`nihhao` 为第二候选；原始拼音字母保持不变，回车仍可提交原始字母。

严格质量脚本目前保留 3 个失败并返回非零：`qingsaomazhifu → 请扫码支付`、`woxiangdawangyueche → 我想打网约车`、`woyaokanduanshipin → 我要看短视频`。对应词都存在，完整图搜索实际只用 69 / 128 / 107 次索引查询，没有撞到 160 次上限。扩大到 16 条路径也不能让期望句进入前八；源频率与缺少语料上下文使“清扫吗支付”“我想大王余额车”“我要砍断视频”更高。当前模型能完成连续拼音组句及用户学习，仍不能保证未学习任意句子的语义首选。下一步应引入可审计的语料上下文评分，而非为三个示例加权。

语料中这三项另以 `assessment` 元数据公开标识。默认严格模式仍运行并检查全部 396 例、保留每条失败并返回非零；`-Acceptance` 同样运行和记录全部语料，单独检查 393 项日常词 / 纠错 / 已支持整句的要求，并输出日常验收和完整评估各自的数量与失败数。这不改变模型和候选阈值，也不把完整评估标记为全通过。最终 396 例运行数据是在新增该输出模式前取得；追加输出模式仅编译检查，不重复运行模拟器，以免干扰正式发布验证。

真实平台词典 + Native 个性化回归独立验证：`kd → 快点` 初始第 15 位，一两次选择不改变，12 次后第一，重开仍第一；分段选择“我要看”再选“短视频”，最后一个词和完整组合每轮各记录一次，前两轮不新增整句 exact，第三轮能以 `woyaokanduanshipin / wykdsp` 召回“我要看短视频”并持久化。预览和禁止学习时文件及计数不变。完整输出见 `input-language-results.txt`。

模型编译现在验证实际序列化的 413 个完整拼音 ID 与 v0.4 逐项同序；17,102 项汉字 / 读音索引、234,996 个存储词条和最长八字词均在原格式容量内。升级测试用旧模型实际选择“你好”“轻”“语”生成用户词“你好轻语”，随后用旧模型、新模型重开同一文件，词仍首位且可完整提交。禁止学习和预览期间的原用户词文件字节完全一致。原生分段选词“你好”后选择“世界”的学习上下文也验证为“你好”。

扩词后原生 100 个 milestone / 600 个 parsing mark 的容量在密集随机输入中更易耗尽。修复按实际已分配标记数发布句柄；没有分配 DMI 路径时清空旧的半拼缓存候选，避免矩阵节点引用未分配内存。保持原有池容量，不删除用户词数据。修复后原 `EngineAdapterSmoke` 全部通过，包括原种子的 100 组 64 字符随机输入 / 删除、1,000 组快速输入 / 删除、最长组合、分段选词、完整预览、候选 ID 恢复和禁止学习。最终结果在 `engine-smoke-results.txt`、`engine-adapter-results.txt` 中。

时延是后台候选搜索耗时，不是触控、动画或真机端到端时延。严格评估样本的 2,835 次增量查询测得中位 0.389 ms、95 分位 14.218 ms、最大 27.573 ms，原始记录已保留在 `test-results/v0.5-chinese-quality-strict.txt`。最后验收复跑同样 2,835 次，为 0.411 / 14.604 / 133.812 ms（中位 / 95 分位 / 最大），候选质量统计不变；单次尾延迟会随共享系统负载变化。此前与 APK 构建及 IME UI 回归共享模拟器时，同协议 389 例为 0.541 / 32.119 / 205.234 ms，反映共享负载差异。首次词库安装、类加载和冷启动应单独测量。真机长时间输入、不同 CPU 和厂商系统仍需安装体验验证。
